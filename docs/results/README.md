# Evaluation results

Generated by `make evaluate` (`python -m simulator.sim.cli evaluate`). Do not edit by hand. All data are synthetic.

| File | What it is |
|---|---|
| `results.json` | Machine-readable results. For each of the two arms and for the orchestrated-minus-baseline difference, every metric as `{mean, ci_low, ci_high, n_reps}` (percentile bootstrap 95% CI over replications; differences paired by replication). Also: `meta` (seed, replications, cases, follow-up days, bootstrap resamples, SHA-256 of the effective parameters and of the pathway YAML, git commit, parameter status counts, any SLA override), `per_replication` (seed and event-log hash per arm per replication, so a rerun can be compared event for event), and `parameters` (every parameter with value, source, status, notes). Sorted keys, floats rounded to 6 places, no timestamps. Byte-for-byte reproducible for the same seed and parameters: `make evaluate-check`. |
| `results.md` | Human-readable report built from the same numbers: plain-English summary, baseline vs orchestrated table with CIs, calibration check against the published completion curves, fairness splits by language and channel, messy-case handling, and the full parameter table with sources and status. Its `generated_at` line is the only content that changes between runs. |

Metric names in `results.json` are flat: for example `completion_180d`, `open_90d`, `time_to_closure_median`, `escalation_precision`,
`fairness.language.ar.completion_final`, `fairness.channel.completion_gap_max`, `messy.wrong_contact.handled_rate`. A `null` means the arm has no
such quantity by design (the baseline has no named owner and no escalations; the automation abstention rate waits for the AI cut) or the
follow-up window is shorter than the metric's horizon.

`git_commit` is the commit the code was at when the file was produced; the results file itself is committed afterwards, so it normally names the parent commit.

To reproduce: `make evaluate` (about 5 seconds on a laptop with 8 workers, about 25 seconds single-process). To see the effect of a
parameter, edit `simulator/params.yaml` and rerun; see [`simulator/README.md`](../../simulator/README.md).
