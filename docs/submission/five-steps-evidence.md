# The challenge owner's five steps: screen, endpoint, test

Written 7 November 2026. For each of the five steps (record the result, prioritise higher-risk people, refer with insurance in mind, remind and navigate until they attend, track the outcome) this table gives the screen a user sees, the API endpoint or event behind it, and the tests that prove it. Every reference was checked against the repository on the date above. **All data is synthetic and time is simulated; this shows the mechanism works, not that it works on real patients.** The one-page version is the [one-pager](ONE-PAGER.md).

**How to read the references.** Screens are routes in `web/src/App.tsx`. Endpoints are `METHOD /path` in `api/app/routers/`. Events are written to the case's append-only log through `POST /cases/{case_id}/events`. Python tests are `path::function`. Web tests are `path::"start of the test title"`. Run the API tests with `make test`, the web unit tests with `make web-test` and the browser tests with `make web-e2e`.

## What these tests do not prove

- **Step 1.** Cases come from a synthetic seed or a simulated feed. No real result feed, Malaffi, Sahatna or UAE PASS connection exists.
- **Step 2.** The tiers for long-term conditions and cervical results use placeholder thresholds that no clinician has signed ([thresholds-to-sign.md](../clinical/thresholds-to-sign.md)). The bowel pathway ranks nothing.
- **Step 3.** The insurance networks are synthetic. The tests prove the routing rule, not that a real plan accepts a real unit.
- **Step 4.** No message reaches a phone: messages are logged, never sent. The outreach policy is unsigned, so nothing goes out automatically. The Arabic text has not been reviewed by a native speaker.
- **Step 5.** The funnel counts synthetic cases in simulated time. The simulated rise in colonoscopy within 180 days (51.0% to 66.8%) was fitted to published trial results and is not evidence of effect, and the labour target of 40% fewer staff minutes is **not met** ([results](../results/results.md)).
