# RBAC matrix

Generated by `tools/check/rbac_matrix.py` (ticket F7, test case T-F9). Do not edit by hand: `make test-security` regenerates it in memory and fails if this file differs (`PYTHONPATH=api python tools/check/rbac_matrix.py --write` updates it).

Every cell is what the running API did, not what the policy table says: the script sends a real request for each route, role and case scope to the app and classifies the answer. Each observed cell is also compared with the policy tables in `api/app/policy.py` (`ROUTE_POLICY`, `EVENT_POLICY`, the owner and own-case scoping), so a difference fails the build. See [decision-matrix.md](decision-matrix.md) for who may do what and why.

## Legend

- `A` allowed past authorisation. The handler ran; whatever it then answered (2xx, 409, 422) is not an access decision.
- `R` denied by role: 403 from the route policy or the event policy.
- `S` denied by case scope: a patient asking for someone else's case (404, indistinguishable from an unknown case), or a `primary_care_owner` / `specialist_owner` acting on a case they do not own (403).
- `U` 401, no valid identity.
- `X/Y` two letters: `X` for the caller's own case, `Y` for another case. One letter: scope makes no difference (the role has no case scope, or the route does not name a case).
- `*` after a letter: the cell is a documented gap, observed behaviour that differs from the intended rule (see Findings).
- Columns: `anon` no token; the six user roles (`pco` = `primary_care_owner`, `spec` = `specialist_owner`, `coord` = `coordinator`, `super` = `supervisor`); `sched` the scheduler service token; `wdog` the watchdog service token; `auto` the automation service token (`system:automation`, A21): it reaches the two scan routes and no event type, because the automation writes its events in process; `agency` the agency supervisor's service token (A22, ADR-033: it may start an agency run and nothing else; the departments have no token).
- "Own case": for a clinician, a case they own; for a patient, the case with their `patient_ref`. "Other": a case owned by another clinician, or another patient's.
